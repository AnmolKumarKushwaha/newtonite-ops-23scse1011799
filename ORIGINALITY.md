# Provenance and originality

The Relay product name, interface composition, application rules, API service, SQL safeguards, tests and explanatory documentation were created for this Newtonite brief. No existing candidate submission or tutorial project was copied into the application implementation.

AI assistance was used to generate and refine the implementation and documentation. The Newtonite candidate brief permits AI tools, while making the candidate responsible for understanding and explaining all submitted behaviour. The candidate should review, run and adapt this code before presenting it as their submission.

The hosted project uses a supplied Vinext/Sites deployment starter. It also uses standard open-source frameworks, libraries and common programming patterns: React, Vite/Vinext, Drizzle, SQLite, Lucide icons and associated tooling. These dependencies and starter infrastructure are not claimed as original inventions. Portable delivery retains the same React application and service logic while excluding unused hosted infrastructure.

No similarity checker has been run, and no zero-similarity or plagiarism-free score is promised. Standard syntax, SQL patterns, dependency files and the wording of required feature names may naturally match other projects. Renaming variables or hiding provenance would not make the engineering more original.

A useful authorship review should focus on the reasoning in ENGINEERING_DECISIONS.md, the working behaviour, the tests, the candidate's own modifications and the ability to explain and change the implementation live.
